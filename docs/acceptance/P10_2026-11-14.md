## 容量和恢复目标

2026-11-14，Windows Docker Desktop/WSL2，Ryzen 9 7845HX 12 核 24 线程，约 15.2 GiB 主机内存，Docker 可见内存约 7.37 GiB，单个 API 进程，SQL 池 5。隔离恢复数据含 3 用户、1 个可用文档、1 个 1024 维分块、4 Agent 和 3 评测运行。回环 HTTP 每个路径 200 次、并发 8、一次预热，门槛 P95 ≤150ms 且全成功。该负载不调用模型。

| 路径 | 成功 | 每秒请求 | P50 | P95 |
| --- | ---: | ---: | ---: | ---: |
| `/health/ready` | 200/200 | 327.3 | 23.6ms | 30.8ms |
| `/api/v1/auth/me` | 200/200 | 326.0 | 23.4ms | 32.7ms |
| `/api/v1/operations/metrics` | 200/200 | 162.9 | 46.2ms | 72.1ms |

小样本恢复门槛为校验备份时点的原文与状态，冷启动和继续工作流总时长 ≤120 秒。最终镜像实测 21.13 秒就绪，23.66 秒得到审批后结果。依赖恢复门槛为 start 返回后 ≤20 秒。模型串行样例的基线 P95 1838ms，来自四个样例，模型调用量和网络时延随供应商变化。当前容量数据用于本机首版基线。公网并发、长时间稳定性、大语料容量、宿主机磁盘损坏与自动异地备份仍待观测。

## 供应链与边界

`uv audit --locked --python-platform linux` 检查 88 个锁定包，当次报告 0 漏洞、0 异常状态。Docker Scout 1.27.0 逐一扫描最终 linux/amd64 应用、PostgreSQL、Redis、NGINX 镜像，门禁过滤有修复版本的 Critical/High。四个镜像均为 0。更新 Python 到 3.13.18、隔离构建工具、修补 zlib、移除最终 Python 镜像中的 pip/ensurepip。PostgreSQL 采用补丁版 17.12 和固定 0.8.7 扩展，仅复制 pgvector 文件，使用 setpriv 替代历史 Go 启动器。NGINX 用固定 Debian 基础镜像及系统包安全升级。上述结果针对扫描规则与当时数据库。

RAG 上下文是非可信数据，生成请求没有工具，引用经过服务端校验。Agent 仅有配置工具且执行时重检所有权，副作用需审批。控制台使用文本渲染。模型可能受注入影响，真实业务内容需按风险评测。供应商凭据、TLS 私钥和实际用户上传内容不作为验收产物。保留与部署入口的完整边界见 [安全文档](../SECURITY.md)。
