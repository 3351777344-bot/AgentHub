# AgentHub Embedding 选型建议

核验日期：2026-11-10。状态：最初建议完整版，用户随后确认使用有免费额度的 qwen3.7-text-embedding-flash、1024 维；真实公开数据验收已通过，独立 10 元预算不变；没有数据库模型或迁移变化。[当前接入说明](EMBEDDINGS.md)。

## 推荐结论

面向公开/脱敏文档的 P4 首版，推荐阿里云百炼中国内地北京地域的 qwen3.7-text-embedding，显式输出 1024 维，先实现稠密向量检索。将 Qwen/Qwen3-Embedding-0.6B 本地独立服务列为数据不得发送第三方时的首选方案。当前最终选择为同地域 Flash，以下表格保留选型对比；出域范围仅公开/脱敏验收文本。

选择理由：中文/中英技术资料检索符合模型定位；云 API 可把当前学习重点放在解析、分块、批处理、幂等与 pgvector，而不同时引入 GPU 推理服务维护。qwen3.7-text-embedding 与 text-embedding-v4 的北京同步输入单价相同，官方发布了针对多语言/中英/代码检索的改进结果，因此新项目优先评测前者；官方评测不能代替 AgentHub 真实样本验证，未声称已测得本项目召回率或时延。

## 候选、维度与费用

费用按北京地域同步调用的输入 token 原价，人民币/百万 token；核验当天价格，不含优惠/免费额度，也不含生成模型、数据库、存储、网络或重试重建成本。

| 方案 | 服务/模型 | 本项目建议维度 | 输入单价 | 取舍 |
| --- | --- | --- | --- | --- |
| 首选云端 | 百炼 qwen3.7-text-embedding | 1024；模型支持 256–2560 的指定档位 | 0.50 元/百万 token | 不占本机 GPU；提供商接收文档片段与查询 |
| 低价候选 | 百炼 qwen3.7-text-embedding-flash | 1024；支持 256/512/768/1024 | 0.125 元/百万 token | 四分之一单价；检索效果需与完整版同样本比较，不凭 Flash 名称推断质量 |
| 兼容备选 | 百炼 text-embedding-v4 | 1024；支持 64–2048 的指定档位 | 0.50 元/百万 token | 可作为对照，不因已有教程多就优先于同价新模型 |
| 本地方案 | 自托管 Qwen/Qwen3-Embedding-0.6B | 1024；模型支持 32–1024 | 无第三方按 token API 费用 | Apache-2.0；需要本机推理、电力与运维；须固定模型 revision、依赖和推理参数 |

示例：假设分块后实际计费输入总量为 500 万 token，则完整版同步向量化约 2.50 元，Flash 约 0.625 元。查询向量化也收费；分块重叠、重复入库、失败重试、更换模型后的重建均可能增加总 token。token 不等于中文字数，不按文件体积直接推算。完整版官方 Batch 文件调用价为 0.25 元/百万 token；这是供应商异步 Batch 产品，不等于普通请求里一次传多条 input，首版先不用它。

## 本机资源与 1024 维理由

只读检测得到约 16 GB 系统内存、NVIDIA GeForce RTX 5060 Laptop GPU，nvidia-smi 报告总显存 8151 MiB。由此判断本地 0.6B 值得做小批量验证，但尚未验证 CUDA/PyTorch/容器组合与吞吐，不承诺固定显存占用或 QPS；应限制批次和片段长度，不能直接按模型最大上下文启动。不要仅凭 Win32 AdapterRAM 判断真实显存，它在本机返回了不准确的值。

每条 1024 维 float32 数值约 4 KiB，2048 维约 8 KiB，均不含数据库行头、原文、元数据和索引。首版选择 1024 维是存储、计算与检索质量之间的起点；高维是否改善效果应由标注问题验证。相同维度不代表相同向量空间，云端/本地模型不得混存或在查询时悄悄互换。

## 隐私取舍

云 Embedding 的输入是原文片段和用户查询，并不是把现成向量交给云端。即使 PDF 文件保留在本地，被抽取并发送的片段仍然出域。本地 pgvector 存储也不能改变这个事实。

官方国际站 ZDR 文档明确只覆盖国际站购买、非中国内地地域及符合资格的调用；不能把它当作北京地域默认零留存承诺。不用于训练与不存储数据是不同问题。北京账号实际输入留存、日志、训练用途、内容安全例外及适用服务条款，本轮没有获得账号级合同确认，应在采用前核对，不能在项目中记为已确认零留存。

本地模型可使向量化过程不将业务文本交给第三方，前提是实际自托管且控制外联、日志、存储与备份。向量不是脱敏或加密结果，也需资源权限控制。

RAG 的第二次出域同样重要：即便 Embedding 完全本地，若将检索到的敏感片段拼进 DeepSeek 提示词，仍违反现有数据边界。敏感资料应同时使用获准的生成服务（例如本地或受控私有部署），不能只更换 Embedding。

## AgentHub 接入与后续业务方案

生成服务保留 DeepSeek；已新增独立的 Embedding 配置/密钥/超时，不能复用 DeepSeek 的地址或密钥。Embedding adapter 已实现并调用向量接口而非 Chat Completions；未来 worker 将原始文档解析/分块，批量生成向量后写 pgvector，在线问题使用同一模型配置生成 query embedding。规范化和 query/document 指令按模型要求处理并记录版本。

未来知识库应保存 provider、地域、model/revision、dimensions、规范化/指令配置及分块版本。数据库使用 vector(1024) 只是形状约束；业务层仍须校验模型身份。换模型、维度或改变影响语义空间的配置时建立新索引版本、重新向量化并切换，禁止在故障时静默回退成另一种 1024 维模型。

建议先用 20–30 个公开/脱敏问题与人工指定正确分块验证 Recall@5、检索延迟及用量，再决定是否采用 Flash、减小维度或增加 reranker。此次没有实际调用以上 Embedding 服务或跑本地模型，性能和效果均待验证。
