# 自动化评测与回归（第九课）

P8 用一套人工标注样例反复运行 RAG 和 Agent，追踪配置变更对召回、引用、行为和延迟的影响。公开合成样例包含两份资料、两个事实问题、一道无证据问题、一次计算工具选择和一次受控权限拒绝。 [固定样例](../../tests/fixtures/p8_regression.json)

## 如何操作

1. 准备专用知识库，通过 P4 上传资料，等文档就绪后获取分块 UUID。使用真实云模型时选公开或脱敏语料。
2. 审核问题、标准证据和期望行为。用 `POST /api/v1/evaluations/datasets` 提交版本和 `reviewed: true`。参考证据使用真实 `gold_chunk_ids`。
3. 数据集有 Agent 样例时先建立只读 Agent 配置。用 `POST /api/v1/evaluations/runs` 创建基线，记录运行 ID。修改 Agent 系统提示、工具列表、`top_k` 或 `min_similarity` 后，在同一数据集提交另一份带版本名的运行。
4. 查询运行状态、`/results` 和 `/report`，再用 `GET /api/v1/evaluations/compare` 比较。需要时在 `/results/{key}/review` 保存人工复核。

`completed` 表示批次执行完毕，样例仍可能失败。API 返回可定位的阶段和错误码，Agent 样例也会返回子运行 ID。 [API 契约](../API_DESIGN.md#p8-自动化评测) · [验收记录](../acceptance/P8_2026-11-13.md)

## 执行链路

| 入口 | 作用 |
| --- | --- |
| [api/evaluations.py](../../src/agenthub/api/evaluations.py) | Bearer 身份、所有权、数据集、批次、取消、结果、人工复核及对比 |
| [evaluations/service.py](../../src/agenthub/evaluations/service.py) | 创建数据集与配置快照，检查语料和权限，持久化终态、报告和对比 |
| [evaluations/worker.py](../../src/agenthub/evaluations/worker.py) | 持 PostgreSQL advisory lock，逐例检查预算与快照、调用业务链路、发布结果 |
| [rag/generation.py](../../src/agenthub/rag/generation.py) | HTTP 问答和 P8 共用 Embedding、pgvector、上下文预算、生成及引用校验。评测结果由 P8 持久化 |
| [agents/worker.py](../../src/agenthub/agents/worker.py) | 目标运行通过原 LangGraph、工具执行器与 PostgreSQL 检查点执行。样例与子运行在同一事务关联 |
| [evaluations/scoring.py](../../src/agenthub/evaluations/scoring.py) | 根据观测值与固定标注计算规则分，聚合人工复核和各项指标 |

数据集摘要涵盖 JSON 样例和就绪语料清单。清单包含知识库处理版本、分块参数、活跃分块 ID、文档版本、文件校验和及分块位置。创建和发布结果时，在短事务中锁定知识库，使用 P4 相同的知识库锁与入库发布、删除协调。模型调用期间释放数据库行锁。增删或重新入库改变清单时，旧版本报告仍可读，继续使用新语料需创建新数据集版本。

配置保存 Agent 内容、工具定义和端点摘要、工作流及评分版本、检索/模型参数和预算。Agent 更新后，已经排队的运行仍用保存的配置。模型或工具目标发生变化时，worker 检查摘要并拒绝执行。更换相同端点背后的模型实现、供应商随机性和外部只读服务实时数据仍会影响重复结果。

## 指标口径

| 指标 | 定义与分母 |
| --- | --- |
| 任务成功率 | 规则通过数 ÷ 数据集全部样例数。失败、跳过、取消的样例均进入分母 |
| Recall@K | 每个有金标且已评分的 RAG 样例，去重后的前 K 命中金标数 ÷ 去重后金标总数，再按样例取均值。搜索阶段失败且已评分时召回为 0 |
| 引用精确率 | 所有已评分 RAG 样例的去重正确引用数之和 ÷ 去重实际引用数之和。引用正确指分块命中人工标注。有标准证据却没有可接受引用会导致样例失败 |
| 工具选择率 | 已评分 Agent 样例中，完成运行且成功工具序列与预期完全相同，并得到指定拒绝且没有额外失败步骤的样例比例。对比使用版本化工具名 |
| 答案规则 | NFKC、大小写折叠和空白归一化后匹配所有指定子串。RAG 同时比较回答/证据不足的预期状态 |
| 延迟 | 已测得样例执行墙钟时间的最近秩 P50/P95，包含实际开始执行的失败样例，排队时间独立体现于运行时间戳 |
| 用量 | 分别聚合已获得的 prompt、completion、Embedding token，附带报告样例数。没有观测值时为 `null` |
| 人工复核 | 所有者为有观测的样例保存独立通过判定和说明。报告给出复核数与人工通过数 |

缺少适用观测时，指标为 `null`，报告同时返回分母。样例可在模型输出无效引用时保留检索观测，判断是检索、模型还是规则断言失配。规则是小范围可验证合同。答案是否真正受到引用支持，需人工阅读原文；当前评分器为规则和人工，模型裁判为可选扩展。对比返回全部样例的状态、指标差值和错误码，并标记从通过变为失败或跳过的回归。

## 预算和恢复

- 数据集最多 30 项。全库一个 evaluation-worker 批次，批内串行。单例上限 1–900 秒，执行批次 1–1800 秒，时间从领取开始。
- 每个样例预留生成输出 token 上限，已知用量结算差额。未知用量保留预留额度。RAG 无证据且从未调用生成时可释放预留。预算覆盖 completion token，prompt/Embedding 用量独立统计。供应商超报触发失败；报告提供 token 观测和预算占用值。
- 在途取消终止本地请求并持久化结果状态。子 Agent 禁止从普通 Agent API 控制或批准。已发出的请求仍可能产生供应商用量，观察不到的用量保留为未知。
- worker 进程中断后，接班者取得锁才处理遗留运行，标记失败并跳过未执行样例。业务运行证据可读取。需要再次评测时，显式创建新运行。
- 可使用已授权的只读工具。写入或高风险工具在批次创建时被拒绝，图的审批护栏也继续生效。小样本和串行配置适用于本地回归，容量及保留策略在 P10 验证。

## 学习检验

1. 两个问答的 Recall@2 都为 1，候选的通过率却下降。需要查哪几个字段，才能判断问题在模型还是检索？
2. 为什么调用没有返回 usage 时，报告和预算各要保存一个不同的数值？
3. 为什么快照既要保存 Agent 配置，也要检查知识库清单？

代码练习：给公开样例增加一个由现有资料能回答的问题，标注证据分块和答案关键词，跑无外网回归并解释新增样例怎样改变分母。

项目思考：新检索配置提高了 Recall@K，但 P95 延迟翻倍。你会如何用同一套样本设定上线门槛，并处理样本数量偏少的问题？

面试可从这条链路讲起：同一语料如何对比两次配置、为什么宏平均召回与微平均引用口径不同、怎样避免数据泄漏、在途取消时怎样处理未知用量。常见错误包括用最终答案代替工具观测、用字符串命中代表语义正确、把跳过当成功、用少量合成样例推断线上质量。另一种方案是独立任务队列与评测框架，适合需要并行、多模型裁判和报表治理的阶段，接入时仍要复用平台的权限及执行合同。
