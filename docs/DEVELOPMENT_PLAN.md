# AgentHub 分阶段开发计划

最后更新：2026-11-10。状态：P0—P3 已完成，P4—P10 未开始。证据见 [P1 验收](acceptance/P1_2026-11-09.md)、[P2 验收](acceptance/P2_2026-11-10.md)、[P3 验收](acceptance/P3_2026-11-10.md)。

## 一、目标、范围与完整项目的定义

用户已确认首版在本地通过 Docker 运行，面向单组织使用，逐步补齐企业能力。本计划覆盖完整首版的实现路径，不是已实现功能清单；实际进度以 [项目状态](PROJECT_STATUS.md) 为准。

完整首版需要形成一条可重复验证的真实链路：

> 登录 → 建立知识库 → 上传与处理文档 → 检索并引用原文回答 → 配置 Agent 及授权工具 → 运行与恢复工作流 → 批量评测 → 查看日志与指标 → 部署、备份和恢复。

首版必须覆盖六个业务方向：知识库、Agent 运行、工具/MCP、LangGraph 编排、自动化评测、日志监控与部署，并提供可用的管理与聊天界面。仅有 Swagger 页面或命令行演示，不算完整首版。

首版包含单组织内多用户与基本角色权限，但不承诺多租户 SaaS、企业 SSO、跨机房高可用、任意代码执行、多 Agent 群体协作、可视化拖拽编排或 OCR 全格式解析。它们在首版稳定后按实际需求扩展。企业级是持续达到的工程目标，不能凭功能数量宣称已满足生产要求。

### 首版资源边界

- 模型服务通过环境配置接入；供应商、生成/Embedding 模型、硬件要求和调用预算在 P3 确认。
- 本地 Docker 部署不等于模型离线推理。是否完全离线是独立需求，当前未确认；不能默认本地机器具备推理显卡。
- 首批文档支持 UTF-8 TXT、Markdown 和可提取文字的 PDF。扫描 PDF、复杂表格和 DOCX 作为后续扩展。
- 首版默认只允许管理员配置受信任的工具/MCP 服务，不允许普通用户上传并执行任意 Python 或 Shell。
- 不预先承诺固定工期；每阶段按验收结果推进。外部模型、硬件和样本集可能影响耗时与质量。

## 二、整体顺序与里程碑

主顺序：P0 → P1 → P2 → P3 → P4 → P5 → P6 → P7 → P8 → P9 → P10。

认证、日志、基础测试和安全边界在早期建立，后续持续完善；P10 负责全链路检验，而不是到发布前才开始做这些工作。为便于学习与定位问题，默认逐阶段推进；独立子任务可在需求允许时调整顺序。

| 里程碑 | 阶段出口 | 能力 | 交付状态 |
| --- | --- | --- | --- |
| M0 规划基线 | P0 | 能看懂现状、范围、架构和后续任务 | 已完成 |
| M1 工程底座 | P2 | 本地可启动、可迁移、有认证和基础权限 | 已完成 |
| M2 知识库闭环 | P5 | 真实文档入库、检索、问答与可追溯引用 | 未开始 |
| M3 Agent 闭环 | P7 | 受控工具/MCP 调用、状态持久化和工作流恢复 | 未开始 |
| M4 产品闭环 | P9 | 自动化评测与可操作的管理/聊天界面 | 未开始 |
| M5 完整首版 | P10 | 全链路通过，能部署、观测、备份恢复并交付 | 未开始 |

### P1：工程底座与本地基础设施

依赖：P0。位置：全部业务模块的公共运行基础。

- [x] P1-01 验证解释器与 Docker/Compose；初始化 Git、.gitignore、配置示例和依赖管理，锁定实际验证的版本。Python、Git、依赖锁定、Docker Desktop/Engine/Compose 及真实运行已验证。
- [x] P1-02 建立模块化 Python 包、FastAPI 应用工厂和配置加载；敏感字段不出现在日志或响应中。
- [x] P1-03 实现请求 ID、结构化日志、统一异常处理、健康与就绪检查；依赖不可用时就绪检查真实失败。
- [x] P1-04 提供 Dockerfile 与 Compose：API、PostgreSQL + pgvector、Redis、持久化卷；数据库和 Redis 不默认暴露公网。实际构建启动、依赖停止/恢复、保留卷的容器重建与数据保留验收均通过。
- [x] P1-05 建立 pytest、格式/静态检查与类型检查入口；为 CI 准备一致的本地命令。
- [x] P1-06 创建根 README、API_DESIGN、DEPLOYMENT、TESTING 和基础模块文档。

数据库：连接与扩展可用性验证，不创建业务表。数据库模型和 Alembic 在 P2 引入。

验收：干净环境可按文档构建启动；健康检查成功；暂停依赖后就绪检查失败；错误响应含请求 ID 且不泄露配置；基础测试和质量检查通过。若 Docker 环境不可用，应记录该阶段尚未完成容器验收。

学习：应用入口、依赖注入、配置、环境隔离、Docker 网络与持久化。

### P2：数据持久化、身份认证与权限基础

依赖：P1。位置：所有资源操作、会话和审计的身份与事务基础。

- [x] P2-01 引入 SQLAlchemy 会话管理与 Alembic，建立迁移规范、事务边界和独立测试数据库。
- [x] P2-02 实现用户、角色及必要认证数据；管理员隐藏输入 CLI 初始化，无默认口令或公开注册。
- [x] P2-03 实现登录、当前用户、过期、退出/改密/角色状态撤销；Argon2id 与数据库会话方案见 ADR-009。
- [x] P2-04 建立 admin/member 与当前用户资源所有权；默认资源私有、共享显式建模；后续资源和后台任务须逐模块落实，当前未虚构共享实现。
- [x] P2-05 管理变更与基础审计同事务；认证失败、越权、失效凭据与并发管理均已测试。
- [x] P2-06 创建 DATABASE、SECURITY、身份模块教学文档并同步 API、架构与测试说明。

数据库：新增实际需要的身份与审计模型；表名、字段、约束在实施前设计并通过 Alembic 迁移交付，不以本计划替代数据库设计。

验收：空库迁移成功；升级路径可验证；合法登录可用；无凭据、错误凭据、过期和越权请求均被拒绝；API 错误符合文档；密码与令牌不明文记录。降级只在可丢弃测试库演练，不擅自删除真实数据。

学习：ORM、事务、迁移、身份认证与授权的区别、资源权限。

### P3：模型接入、会话与消息

依赖：P2。位置：RAG 和 Agent 共用的模型调用与会话基础。

- [x] P3-01 确认首个生成模型和 Embedding 服务、认证配置、向量维度、调用预算与数据出域要求。
- [x] P3-02 定义最小模型适配接口，先接通一个真实提供商；不一次封装所有供应商。
- [x] P3-03 支持结构化输出/工具调用所需能力声明、超时、限流错误和有边界重试；记录模型标识与可获得的 token 用量。
- [x] P3-04 实现会话、消息历史、分页与所有权校验；明确失败/取消时消息状态。
- [x] P3-05 提供普通聊天及 SSE 流式响应；规定终止事件、错误事件和断线后的查询行为。
- [x] P3-06 更新模型/会话文档、数据库迁移、API 和测试说明。

数据库：会话、消息及实际需要的调用记录。模型凭据从环境或受控凭据配置读取，不把真实密钥写入仓库。

验收：真实模型可以完成一次流式和一次非流式对话；会话历史重启后保留；超时、上游错误、断线与越权行为可重复验证。自动化测试允许用明确标识的测试替身控制异常；真实调用必须单独列出，不以替身通过冒充接入成功。

学习：HTTP 客户端、异步 I/O、SSE、消息持久化、token 与成本记录。

### P4：知识库、文档处理与向量入库

依赖：P2、P3。位置：RAG 的离线知识准备链路。

- [ ] P4-01 实现知识库与文档的增删查、分页、权限和文档状态；限制上传大小、类型和路径。
- [ ] P4-02 使用 Docker 持久化卷保存原始文档；保存校验和、来源和版本，处理同名与重复上传。
- [ ] P4-03 实现 TXT、Markdown、文本 PDF 解析与清洗；空文档、乱码、扫描 PDF 给出明确失败原因。
- [ ] P4-04 实现可配置分块、重叠与原文位置；记录分块策略、模型标识、向量维度及版本。
- [ ] P4-05 接入真实 Embedding，批量写入 PostgreSQL + pgvector；更换模型/维度需要重新入库，不能混用不兼容向量。
- [ ] P4-06 引入独立 worker；在实施前选择 Redis 任务队列库并记录决策；任务状态持久化、重试与幂等、失败回收、删除中的并发一致性一起实现。
- [ ] P4-07 同步数据库、API、知识库模块、后台任务与部署文档。

数据库：知识库、文档、分块、向量和入库任务等实际模型及迁移。确保删除后的文档不会因迟到的任务重新出现；数据库与文件操作需要可恢复的补偿流程。

验收：三类文档均可真实入库并追溯原文；失败可查询与重试；重复执行不生成重复有效分块；worker 中断后可恢复或明确失败；文档删除后不可检索，后台任务不能复活数据。使用真实 PostgreSQL + pgvector 验证，SQLite 不能代替向量集成测试。

学习：ETL、分块、Embedding、向量空间、队列、幂等与最终一致性。

### P5：RAG 检索问答与引用

依赖：P4、P3。位置：连接知识库与语言模型的在线问答链路。

- [ ] P5-01 实现问题向量化、限定知识库和权限范围的相似度检索、Top-K 与阈值配置。
- [ ] P5-02 小数据量先建立精确检索基线；是否加入 HNSW/混合检索/重排，以数据与评测结果决定。
- [ ] P5-03 组装有长度预算的上下文和提示词，将检索资料视为不可信输入，避免资料内指令改变系统权限。
- [ ] P5-04 返回答案及可验证的文档、分块/页码引用；处理无结果、低相关度和来源被删除的情况。
- [ ] P5-05 接入会话与流式响应，记录检索耗时、模型耗时、可获得用量和失败原因。
- [ ] P5-06 建立小型人工标注检索样本与正确/无答案/越权样例，更新 RAG 文档。

数据库：按实际需要增加检索或回答追踪字段，变更均通过迁移。

验收：真实上传文档可被问答命中，引用能定位原文；无证据时给出证据不足的结果；其他用户未授权文档不进入上下文；记录指定样本下的检索质量与延迟，不用少量演示声称消除幻觉。

学习：召回与生成的分工、向量距离、上下文预算、引用可信度、RAG 失败排查。

### P6：工具注册与 MCP 集成

依赖：P2、P3，知识库检索工具复用 P5。位置：为 Agent 提供统一、可授权的外部能力。

- [ ] P6-01 定义工具描述、输入输出 schema、版本、超时、权限和副作用等级；建立统一执行与审计入口。
- [ ] P6-02 接入真实的知识库检索工具和受控示例工具，验证参数后执行；禁止 eval 和任意 Shell 透传。
- [ ] P6-03 使用 MCP SDK 接入受控本地服务，完成工具发现、schema 转换和调用；锁定实际兼容的协议与 SDK 版本。
- [ ] P6-04 支持管理员配置的远程 MCP，处理适用的认证、地址验证、重定向及 SSRF 边界；未完成前不宣称支持任意服务。
- [ ] P6-05 对本地进程/容器配置最小文件与网络权限；令牌按目标服务隔离，不将平台凭据直接透传。
- [ ] P6-06 测试未知工具、非法参数、未授权、超时、服务断连与危险操作；同步工具/MCP、SECURITY 和 API 文档。

数据库：工具配置、服务配置及调用审计等实际模型。密钥引用与普通配置分离。

验收：内置工具、受控本地 MCP 和受控远程 MCP 均至少完成一次真实调用；未知工具与未授权调用被拒绝；失败有结构化记录；MCP 服务重启不拖垮 API。高副作用工具在 P7 审批链路完成前保持禁用。

学习：JSON Schema、工具调用与函数执行的区别、MCP client/server、进程与网络信任边界。

### P7：LangGraph Agent 与工作流运行

依赖：P3、P5、P6。位置：整合模型、检索和工具的核心执行系统。

- [ ] P7-01 实现 Agent 配置：系统提示、模型、可用知识库与工具、步数/时间/用量预算。
- [ ] P7-02 定义 LangGraph 状态、节点、条件边和消息更新规则；先提供可解释的固定工作流模板。
- [ ] P7-03 实现模型决策 → 参数/权限检查 → 工具执行 → 结果反馈 → 继续或结束的闭环，避免无限循环。
- [ ] P7-04 持久化运行、步骤与事件；区分运行 ID、业务会话 ID 和图线程 ID，逐次校验归属。
- [ ] P7-05 使用持久化 checkpointer 实现状态恢复；重放时通过幂等键或执行账本控制外部副作用，不能只靠检查点宣称恰好执行一次。
- [ ] P7-06 实现暂停、取消和人工审批；高副作用调用须展示参数、绑定具体运行和审批内容，防止重复批准与参数被替换。
- [ ] P7-07 提供运行事件流与状态查询，测试失败恢复、预算耗尽、取消和拒绝审批；同步架构、数据库和 Agent/工作流文档。

数据库：Agent 配置、运行、步骤、审批、工具执行记录和检查点；框架自有表也纳入受控初始化/升级及备份流程，避免与 Alembic 职责混淆。

验收：至少一个真实模型 Agent 能检索知识库并调用授权工具；一个多节点工作流完成分支与审批；重启后可恢复；超预算可结束；重试/恢复不会重复执行已确认的副作用；不同用户不能读取或恢复他人的运行。

学习：状态机、图状态与 reducer、条件边、检查点、恢复语义和人工介入。

### P8：自动化评测与回归

依赖：P5、P7。位置：验证效果与防止提示词/模型/检索策略变更导致退化。

- [ ] P8-01 建立可版本化评测集，支持问题、参考证据、期望行为与必要标签；样本需人工审核且不含真实敏感资料。
- [ ] P8-02 评测检索 Recall@K、引用正确性、任务成功率、工具选择、延迟及可获得的 token 用量；定义分母和计算规则。
- [ ] P8-03 区分规则评分、人工评分和可选模型裁判；无可靠价格时不编造金额，模型裁判不能作为唯一真值。
- [ ] P8-04 实现批量运行、超时、取消、失败记录、并发限制和预算；固定数据/配置快照以便复现。
- [ ] P8-05 保存与对比报告，将已知失败样例纳入回归；为 CI 划分无外网测试与显式启用的付费评测。
- [ ] P8-06 同步评测模块、数据库、API 和测试文档。

数据库：评测集版本、样例、评测运行、逐项结果及报告等实际模型。

验收：同一评测集可对比两个明确版本的配置；错误样例能定位到检索、模型或工具步骤；失败/跳过不能当作成功；真实模型评测结果与确定性单元测试分开报告。

学习：离线评测、基线、数据泄漏、指标取舍、随机性和回归。

### P9：管理与交互界面

依赖：P2—P8 已具备的 API。位置：让用户能直接操作全部核心功能。

- [ ] P9-01 根据真实交互需求选择简洁前端方案，记录决策与新增依赖，不预先引入庞大框架体系。
- [ ] P9-02 实现登录、退出、权限反馈与必要管理入口，不把模型密钥交给浏览器。
- [ ] P9-03 实现知识库、上传、文档处理状态、失败重试与引用查看。
- [ ] P9-04 实现流式聊天、Agent 配置、运行步骤、取消/审批和错误恢复提示。
- [ ] P9-05 实现工具/MCP 管理、评测发起与报告对比、运行日志查看。
- [ ] P9-06 验证关键操作的端到端行为、空状态、加载、失败与键盘操作；将界面纳入 Docker 启动与使用文档。

数据库：优先复用已有接口与模型；新需求确需改动时补迁移，不能让界面直接连接数据库。

验收：用户无需手写 API 请求即可完成完整业务链路；页面显示真实后台状态；未授权用户无法通过界面或直接 API 绕过限制；流式中断、失败和重试可理解且可操作。

学习：前后端契约、认证状态、事件流、轮询与推送、端到端测试。

### P10：运维、安全加固与完整发布验收

依赖：P1—P9。位置：把模块组合为可交付、可维护的完整首版。

- [ ] P10-01 完善结构化日志、请求/任务/运行关联 ID、指标与必要链路追踪；脱敏并制定日志与检查点保留策略。
- [ ] P10-02 验证上传限制、提示注入边界、认证/授权、限流、CORS、MCP 网络/进程边界和供应链依赖；记录尚存风险。
- [ ] P10-03 完善 Compose、启动顺序、迁移步骤、非 root 运行、健康检查和优雅退出；配置明确区分本地与对外部署。
- [ ] P10-04 建立数据库、原始文件与图检查点的一致性备份及恢复流程；在隔离环境进行一次真实恢复演练。
- [ ] P10-05 在记录硬件、模型、文档规模与并发条件的情况下测量性能，确定并验证发布基线；演练依赖断开、worker 崩溃和模型超时。
- [ ] P10-06 建立 CI 门禁、构建产物、配置示例、升级与回滚说明；回滚需同时考虑代码、数据库和外部副作用，不承诺所有迁移都能无损降级。
- [ ] P10-07 运行完整验收链路，清理过时说明，发布明确版本与已知限制，完成架构讲解和独立修改练习。

数据库：只实施经过评测必要的索引或保留策略变更，附迁移与恢复步骤。不得在真实数据上直接执行破坏性演练。

验收：满足第四节全部发布条件，并在开发记录中保存命令、环境、结果和未验证项；未满足时不能标记完整项目已交付。

学习：可观测性、故障定位、容量与延迟、备份恢复、发布和回滚。

## 四、完整首版发布条件

- [ ] 可以在干净、满足前置条件的环境按文档构建与启动全部服务。
- [ ] 至少两名测试用户验证认证、角色和资源权限，覆盖直接 API 与后台任务。
- [ ] 使用真实生成模型、Embedding 与三类文档完成知识库问答，引用可定位。
- [ ] 使用真实内置工具、本地 MCP 和受控远程 MCP 完成调用，验证超时和权限边界。
- [ ] 至少一个 Agent 和一个多节点工作流完成运行、审批、取消与恢复验证。
- [ ] 评测集、配置版本和结果可以追溯；关键回归样例满足已记录门槛。
- [ ] 管理与聊天界面能完成核心流程，无需操作数据库或手写请求。
- [ ] 单元、PostgreSQL/Redis/MCP 集成、关键端到端和质量检查通过；付费真实调用单独记录。
- [ ] 日志可串联请求、入库任务和 Agent 运行；失败有可定位信息且不泄露凭据。
- [ ] 数据库、原始文件和检查点完成备份恢复演练；部署、升级与回滚文档经过操作验证。
- [ ] 性能与恢复目标根据明确的环境和负载设定并验证，没有用未测量的数字宣传能力。
- [ ] 文档与实际代码一致，已知限制公开记录，用户学习状态有独立证据。

## 五、每次开发的固定交付流程

1. 读取文档索引、项目状态及相关模块说明，核对实际代码。
2. 说明需求、模块位置、依赖、涉及文件、数据库影响和风险，再开始实施。
3. 完成一个可以验证的小任务；优先复用，避免无关改动和未检查的大量依赖。
4. 运行适用测试、语法/类型检查与真实依赖验证；准确区分通过、失败、跳过和未执行。
5. 更新状态、相关 API/数据库/模块文档、开发记录及必要技术决策。
6. 结合真实代码讲解实现、执行顺序、模块交互、设计理由、替代方案、常见错误和面试问题。
7. 提供 2—3 个理解问题、1 个简单代码修改任务及 1 个项目思考题；收到回答或检查练习前不标记已掌握。
8. 检查差异与敏感信息；仅在整个 P 阶段节点的代码、测试和文档全部完成后提交，中间步骤不提交。提交标题使用 `P阶段编号:中文说明`，例如 `P2:完成数据持久化、身份认证与权限基础`。未获远程发布授权时不推送或公开部署。

### 各阶段学习检验方向

以下是练习安排，不代表已经授课或完成。实际开发时根据真实函数和文件细化题目，不提前给出全部答案。

| 阶段 | 理解问题方向（每次选 2—3 个） | 简单代码修改任务 | 项目思考题 |
| --- | --- | --- | --- |
| P1 | 工厂函数、依赖注入、健康与就绪的区别 | 为健康接口增加受测试覆盖的版本字段 | 数据库故障时，哪些接口应继续可用？ |
| P2 | 认证与授权、事务提交、迁移作用 | 给实际资源接口补一个越权拒绝测试 | 如何迁移到未来的组织级权限？ |
| P3 | 流式事件、超时重试、会话所有权 | 为实际模型调用增加一个可配置超时 | 浏览器断开后，生成任务应如何处理？ |
| P4 | 分块重叠、向量维度、任务幂等 | 修改分块配置并验证边界和入库结果 | 文档删除与入库任务同时执行会发生什么？ |
| P5 | 检索和生成的区别、Top-K、引用校验 | 调整 Top-K 并比较固定样本的结果 | 回答错误时怎样判断是召回还是生成问题？ |
| P6 | schema、MCP client/server、工具权限 | 给一个已有工具增加参数约束和测试 | 外部 MCP 工具描述被篡改会影响什么？ |
| P7 | 状态更新、条件边、检查点与幂等 | 给工作流增加一个失败处理分支及测试 | 恢复执行如何避免重复发起有副作用的操作？ |
| P8 | Recall@K、基线、模型裁判局限 | 加入一个真实失败样例并运行对比 | 质量提升但成本翻倍，如何决定是否发布？ |
| P9 | API 契约、认证状态、断线处理 | 给上传失败状态增加明确重试提示 | 界面与后台状态不一致时以什么为准？ |
| P10 | 关联日志、恢复目标、升级回滚 | 增加一个实际运维指标或告警条件 | 只备份数据库为什么可能无法恢复知识库？ |

## 六、首版后的企业能力扩展

以下方向尚未开始，不作为已经实现的首版能力。进入扩展前需重新做范围与验收设计。

1. 多租户：组织/成员关系、行级或库级隔离、全链路租户上下文、跨租户测试、存量数据迁移。
2. 企业身份与治理：OIDC/SSO、细粒度权限、凭据托管、审批策略、审计导出与留存。
3. 扩展与可靠性：多副本、任务调度、限额与计费、集中对象存储、数据库高可用和恢复演练。
4. 深化 AI 能力：混合检索与重排、OCR/多模态、连接器、工作流版本管理和可视化编排。

默认先让单组织完整首版满足 M5，再根据真实瓶颈扩展；不提前引入微服务、Kubernetes 或专用向量数据库。

## 七、技术依据与核验

以下官方资料于 2026-11-04 查阅，用于校正设计风险，不代表已安装对应库或验证运行：

- [FastAPI Background Tasks](https://fastapi.tiangolo.com/tutorial/background-tasks/)：重型后台处理可使用独立任务系统。因此文档入库与批量评测规划为独立 worker，具体队列库实施前选定。
- [LangGraph Persistence](https://docs.langchain.com/oss/python/langgraph/persistence)：区分线程内检查点与跨线程数据；内存检查点不能代替重启后的持久化恢复。
- [pgvector 官方说明](https://github.com/pgvector/pgvector)：精确检索与近似索引存在质量/性能取舍；先建立质量基线再决定索引。
- [MCP Security Best Practices](https://modelcontextprotocol.io/docs/tutorials/security/security_best_practices)：考虑令牌透传、SSRF 和本地服务信任边界，不能只实现调用协议而忽略执行权限。

库、协议及容器镜像的版本在对应阶段实施时重新核对并锁定，避免路线图充当未经验证的兼容性承诺。

P3 2026-11-10 阶段出口：全部六项完成。生成模型为 DeepSeek deepseek-flash；Embedding 经用户确认切换为百炼北京 qwen3.7-text-embedding-flash、1024 维，真实公开数据验收通过。两类服务各自授权 10 元验收预算，仍限公开/脱敏数据。消息历史补充真实 Uvicorn 进程终止后启动新进程读取测试，全部回归及文档同步完成。阶段证据见 P3 验收；完整版额度失败作为开发日志历史保留，不再当作当前阻塞。P4 尚未实施。
